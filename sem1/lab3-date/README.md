## Теоретическое обоснование
Класс в объектно-ориентированном программировании представляет собой пользовательский тип данных, объединяющий поля (состояние) и методы (поведение). Экземпляр класса в оперативной памяти называется объектом.

Инкапсуляция защищает внутреннее состояние объекта от некорректного прямого вмешательства извне:
* Спецификатор `private` скрывает поля и вспомогательные функции от внешнего кода.
* Спецификатор `public` определяет открытый интерфейс класса.
* Геттеры (методы чтения) возвращают значения полей без права модификации объекта. Такие методы помечаются спецификатором `const`.
* Сеттеры (методы записи) контролируют изменение полей, проверяя корректность новых значений перед их сохранением.

Жизненным циклом объекта управляют специальные функции-члены:
* Конструктор инициализирует поля объекта при его создании. Конструктор вызывается автоматически, не имеет возвращаемого типа и носит имя класса. Список инициализации (`: day(d), month(m)`) инициализирует поля до входа в тело конструктора.
* Конструктор копирования создает дубликат объекта на основе существующего экземпляра того же типа.
* Деструктор вызывается автоматически при выходе объекта из области видимости или при удалении оператором `delete`, освобождая захваченные ресурсы.

## Пошаговое выполнение работы

### Шаг 1. Проектирование заголовка класса (`Date.h`)
В закрытой секции объявлены поля дня, месяца и года, а также вспомогательные функции проверки високосного года и допустимости даты:

```cpp
#pragma once
#include <string>

class Date {
private:
    int day;
    int month;
    int year;

    bool isLeap(int y) const;
    int daysInMonth(int m, int y) const;
    bool isValid(int d, int m, int y) const;

public:
    Date();
    Date(int day, int month, int year);
    Date(const Date& other);
    ~Date();

    int getDay() const;
    int getMonth() const;
    int getYear() const;

    void setDay(int day);
    void setMonth(int month);
    void setYear(int year);

    bool isLeapYear() const;
    void addDays(int count);
    void addFiveDays();
    std::string toString() const;
};
```

### Шаг 2. Реализация конструкторов и деструктора (`Date.cpp`)
Конструктор по умолчанию задает базовую дату `01.01.2000`. Параметризованный конструктор проверяет валидность даты с учетом календаря и високосных лет:

```cpp
Date::Date() : day(1), month(1), year(2000) {
    std::cout << "Вызван конструктор по умолчанию: " << toString() << std::endl;
}

Date::Date(int day, int month, int year) : day(1), month(1), year(2000) {
    if (isValid(day, month, year)) {
        this->day = day;
        this->month = month;
        this->year = year;
    } else {
        std::cout << "Ошибка: даты " << day << "." << month << "." << year
                  << " не существует, установлена дата по умолчанию." << std::endl;
    }
}

Date::~Date() {
    std::cout << "Вызван деструктор для даты " << toString() << std::endl;
}
```

### Шаг 3. Методы доступа и бизнес-логика (вариант 1)
Сеттеры гарантируют, что объект никогда не перейдет в невалидное состояние (например, 29 февраля в невисокосный год или 31 число в апреле):

```cpp
void Date::setMonth(int month) {
    if (month < 1 || month > 12) {
        std::cout << "Ошибка: месяц должен быть от 1 до 12." << std::endl;
    } else if (!isValid(day, month, year)) {
        std::cout << "Ошибка: в месяце " << month << " нет дня с номером " << day << "." << std::endl;
    } else {
        this->month = month;
    }
}
```

Реализованы функции варианта: определение високосного года и добавление 5 дней с корректным переходом через границу месяцев и лет:

```cpp
bool Date::isLeapYear() const {
    return (year % 4 == 0 && year % 100 != 0) || (year % 400 == 0);
}

void Date::addFiveDays() {
    for (int i = 0; i < 5; ++i) {
        ++day;
        if (day > daysInMonth(month, year)) {
            day = 1;
            ++month;
            if (month > 12) {
                month = 1;
                ++year;
            }
        }
    }
}
```

## Контрольные вопросы

### 1. Что такое класс и чем он отличается от объекта?
Класс описывает тип данных, структуру его полей и доступные операции (шаблон или чертеж). Объект является конкретным экземпляром этого класса, занимающим память во время выполнения программы.

### 2. Для чего нужны спецификаторы доступа public и private?
Спецификатор `private` скрывает детали реализации и данные объекта от прямого доступа извне. Спецификатор `public` открывает методы интерфейса, через которые внешний код взаимодействует с объектом.

### 3. В чем суть инкапсуляции?
Инкапсуляция объединяет данные и методы их обработки в единый компонент и изолирует внутреннее состояние объекта от внешнего мира, гарантируя поддержание инвариантов класса.

### 4. Зачем нужны геттеры и сеттеры, если можно сделать поля открытыми?
Открытые поля позволяют внешнему коду присвоить некорректные значения (например, 35 число или отрицательный месяц). Сеттеры валидируют данные до их записи, а геттеры дают доступ только для чтения.

### 5. Что такое список инициализации и почему его предпочтительно использовать?
Список инициализации расположен между заголовком конструктора и его телом. Он инициализирует поля объекта напрямую во время выделения памяти, минуя фазу инициализации по умолчанию с последующим присваиванием. Для константных полей и ссылок список инициализации обязателен.

### 6. Чем конструктор отличается от обычного метода?
Конструктор не возвращает значение (даже `void`), его имя в точности совпадает с именем класса, и он вызывается автоматически системой при создании объекта.

### 7. Для чего нужен деструктор и когда он вызывается?
Деструктор освобождает ресурсы, занятые объектом (закрывает файлы, освобождает динамическую память). Он вызывается автоматически при выходе объекта из блока видимости или при удалении через `delete`.

### 8. Что означает ключевое слово const после списка параметров метода?
Оно указывает, что метод не модифицирует поля вызывающего объекта (`this`). Внутри такого метода все поля рассматриваются как константные, а сам метод может вызываться для константных объектов.
