## Теоретическое обоснование
Статические массивы в C++ выделяются на стеке и имеют неизменяемый размер, заданный на этапе компиляции. Для работы с наборами данных произвольного размера память выделяется в куче (*heap*) через операторы `new[]` и освобождается через `delete[]`.

Класс, владеющий ресурсом (указателем на динамическую память), обязан соблюдать «правило трех»:
* **Деструктор:** освобождает массив оператором `delete[] data` при уничтожении объекта, предотвращая утечки памяти.
* **Конструктор копирования:** выполняет глубокое копирование (*deep copy*): выделяет новый блок памяти нужного размера и поэлементно переносит в него данные оригинала. Если конструктор копирования не перегружен, компилятор сгенерирует поверхностную копию (*shallow copy*), скопировав лишь числовое значение указателя, что приведет к двойному освобождению памяти (*double free*) и аварийному завершению программы.
* **Оператор присваивания:** освобождает ранее удерживаемую память, выделяет новый буфер и копирует данные. Обязательно включает проверку на самоприсваивание (`if (this != &other)`), иначе объект уничтожит собственные данные до начала копирования.

Для разделения логического размера и выделенной емкости класс хранит два счетчика: `size` (число активных элементов) и `capacity` (размер выделенного буфера).

### Шаг 2. Реализация «правила трех» (`IntVector.cpp`)
Деструктор, конструктор копирования и перегруженный оператор присваивания гарантируют целостность динамической памяти:

```cpp
IntVector::IntVector(const IntVector& other)
    : data(nullptr), size(other.size), capacity(other.capacity) {
    if (capacity > 0) {
        data = new int[capacity];
    }
    for (int i = 0; i < size; ++i) {
        data[i] = other.data[i];
    }
}

IntVector::~IntVector() {
    delete[] data;
}

IntVector& IntVector::operator=(const IntVector& other) {
    if (this != &other) {
        int* newData = nullptr;
        if (other.capacity > 0) {
            newData = new int[other.capacity];
        }
        for (int i = 0; i < other.size; ++i) {
            newData[i] = other.data[i];
        }
        delete[] data;
        data = newData;
        size = other.size;
        capacity = other.capacity;
    }
    return *this;
}
```

### Шаг 3. Доступ по индексу и динамическое расширение
Оператор `[]` проверяет границы диапазона и бросает исключение `std::out_of_range`:

```cpp
void IntVector::checkIndex(int index) const {
    if (index < 0 || index >= size) {
        throw std::out_of_range("Индекс вне диапазона");
    }
}

int& IntVector::operator[](int index) {
    checkIndex(index);
    return data[index];
}
```

При добавлении элементов через `pushBack` емкость буфера удваивается:

```cpp
void IntVector::pushBack(int value) {
    if (size == capacity) {
        int newCapacity = (capacity == 0) ? 1 : capacity * 2;
        reallocate(newCapacity);
    }
    data[size] = value;
    ++size;
}
```

### Шаг 4. Реализация требований варианта 1
Реализованы методы резервирования емкости и оптимизации занятой памяти:

```cpp
void IntVector::reserve(int newCapacity) {
    if (newCapacity < 0) {
        throw std::invalid_argument("Емкость не может быть отрицательной");
    }
    if (newCapacity > capacity) {
        reallocate(newCapacity);
    }
}

void IntVector::shrinkToFit() {
    if (capacity > size) {
        reallocate(size);
    }
}
```

## Контрольные вопросы

### 1. Что такое динамическая память и чем она отличается от статической?
Статическая память выделяется на стеке программы во время компиляции, имеет фиксированный размер и автоматически освобождается при выходе переменной из области видимости. Динамическая память выделяется в куче (*heap*) во время выполнения программы по запросу через оператор `new` и существует до явного освобождения оператором `delete`.

### 2. Для чего используются операторы new[] и delete[]?
Оператор `new[]` выделяет непрерывный блок памяти в куче под массив заданного типа и размера. Оператор `delete[]` вызывает деструкторы элементов и возвращает выделенный блок памяти операционной системе. Использование одиночного `delete` для массива приводит к неопределенному поведению (*undefined behavior*).

### 3. Что такое «правило трех» и почему оно обязательно для классов с ресурсами?
Если класс явно управляет ресурсом (динамической памятью) и требует пользовательского деструктора, он обязан явно реализовать конструктор копирования и оператор присваивания. По умолчанию компилятор создает эти функции с почленным копированием указателей, что приводит к совместному владению одним блоком памяти и ошибкам двойного освобождения (*double free*).

### 4. В чем разница между конструктором копирования и оператором присваивания?
Конструктор копирования создает и инициализирует совершенно новый объект из неинициализированной памяти на основе существующего объекта. Оператор присваивания вызывается для уже существующего объекта, поэтому обязан предварительно освободить старые ресурсы перед копированием новых.

### 5. Что произойдет, если не сделать проверку if (this != &other) в операторе присваивания?
При присваивании объекта самому себе (`v = v`) код сначала освободит старый массив `delete[] data`, после чего попытается прочитать из него данные для копирования. Это приведет к обращению по невалидному указателю (*use-after-free*) и повреждению данных.

### 6. Что такое глубокое копирование и чем оно отличается от поверхностного?
Поверхностное копирование (*shallow copy*) просто дублирует числовое значение адреса в указателе, в результате чего два объекта ссылаются на одну область памяти в куче. Глубокое копирование (*deep copy*) выделяет отдельный независимый блок памяти и копирует туда сами значения элементов.

### 7. Чем отличается метод reserve() от метода resize()?
Метод `reserve(n)` изменяет только емкость буфера (`capacity`), подготавливая память под будущие вставки. Количество элементов (`size`) и сами элементы не меняются. Метод `resize(n)` меняет фактический размер вектора (`size`), удаляя лишние элементы или добавляя новые со значениями по умолчанию.

### 8. Что такое идиома RAII?
Концепция RAII (*Resource Acquisition Is Initialization*) связывает жизненный цикл ресурса со временем жизни объекта. Захват ресурса (выделение памяти) происходит в конструкторе, а гарантированное освобождение происходит в деструкторе автоматически при выходе из блока видимости.
